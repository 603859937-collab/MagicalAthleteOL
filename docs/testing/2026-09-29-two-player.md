# 双人实测记录（2026-09-29）

## 测试方式

- 两个独立浏览器会话，在不同本地端口隔离玩家身份，通过真实界面操作同一房间。
- 浏览器完成前两场：第一场累计小红 3、小明 1；第二场累计小红 7、小明 3。随后在第三场特殊赛道复现连锁展示及可选技能问题。
- 修复后用固定浏览器场景验证：跳过决斗可恢复掷骰；教练移动后，吸盘鱼提示明确标出跟随教练及 0 → 6 格。
- 另以两个独立 WebSocket 客户端，通过公开玩家指令完成整局四场。此自动回归验证服务器与双人同步，不替代浏览器动画检查。

## 发现并修复

1. 起始骰结果被下一阶段覆盖：先展示完整骰点、赢家或平局，再继续。
2. 技能来源与目标不清：增加人物、玩家名、光圈、因果箭头及实际位移。
3. 吸盘鱼提示成“吸盘鱼对吸盘鱼触发”：服务端携带实际跟随对象，前端展示该对象与吸盘鱼之间的关系。
4. 换位后的无目标汇总重复播放：保留真实位移，合并对应汇总事件。
5. 选择期间回滚的临时移动被提前广播：事件只在该动作成功完成后发布，避免继续选择时重复播放。
6. 同一动作包含多个选择时反复弹窗：按顺序保存并重放本次动作的全部已完成选择。
7. 可选目标技能无法拒绝：决斗、换位、催眠、加入两人同格提供“不使用”；必选骰点仍不能跳过。
8. 内部英文技能和角色名、播放中误写等待玩家、窄屏遮挡比分、手动加入后刷新缺少房间链接均已修复。

## 回归结果

- 完整四场 WebSocket 对局：127 次掷骰，65 次技能选择，75 次技能触发，最终小明 16、小红 14。
- 每次更新核对双方版本号、阶段、当前玩家、角色位置和状态、分数、单场结算及冠军一致。
- 每位玩家使用并退场 8 名角色，完成四场并进入 FINISHED。
- 前端：38 项通过；服务端：42 项通过。
- TypeScript 与 Vite 构建通过。构建使用测试 HTTPS API 地址，仅验证构建；未部署。
