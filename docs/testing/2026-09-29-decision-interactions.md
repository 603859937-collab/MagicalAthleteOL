# 技能选择交互审查（2026-09-29）

## 范围

检查技能实现 → DecisionBroker → 游戏公开协议 → 房间权限与超时 → 前端选择提示及提交逻辑。采用离线模拟、单元测试和源码检查，没有运行 UI 自动化。

当前 16 种交互技能都是布尔选择或单选；一次技能可以影响多人，但并不等于玩家需要多选目标。例如啦啦队长选择“使用”后同时影响全部并列最后的角色，测试已验证没有只处理一名。赛前阵容是独立的多选：2 人各选 2 名，3 人可开启各选 2 名，其他情况各选 1 名。

| 交互 | 技能 | 检查重点 |
| --- | --- | --- |
| 使用/不用 | 炼金术士、火箭科学家、魔术师、骰商、吸盘鱼、啦啦队长 | 两条分支、自动选择、骰点/跟随信息 |
| 可跳过的目标单选 | 决斗家、催眠师、人字拖、电灯泡 | 每个目标、跳过、自动选择、目标实际效果 |
| 必选单选 | 蛋、双胞胎、模仿猫、幕后主脑、天才、长腿 | 每个候选、禁止非法跳过、复制/预测值、骰点选择 |

## 已修复

1. **同一技能连续提问时，后一个问题的自动答案可能使用前一个问题的上下文。** InteractiveAgent 在回放旧答案前就计算 pending 的自动答案，只比较角色和技能名。用 `(6,1)`、`(1,6)` 两个连续候选集复现：第二次自动选最大值却得到 1。布尔选择也存在相同问题。现在回放完旧答案后才计算当前自动答案。两个测试分别验证单选和布尔场景。该缺陷是在代理/决策器边界构造复现；本次正常阵容模拟没有单独定位到对应的自然触发链。
2. **引擎的超时入口未校验 decisionId。** 手动提交会校验，timed_out=True 则直接处理当前问题。现在两者都验证问题 ID。房间层原本已有当前问题检查，此修复补齐引擎入口保护，不能据此声称线上定时器已发生串题。
3. **提示不足以支持用户判断。** 天才的“预测”误写成“选择本次使用的骰点”；人字拖缺少跳过正常移动的代价；吸盘鱼选择时移动尚未提交，无法从棋盘判断跟随对象和目的地。现已分别修正，并补全其他技能的作用及可跳过提示。
4. **火箭科学家的选择没有 rollPreview。** 原代码只处理掷骰修改窗口，遗漏 RollResultEvent。现已附带实际骰点与结果 ID，测试验证移动尚未提交时也可读取预览。
5. 角色目标选项现在附带所属玩家和位置，使用提问时的候选对象生成，避免回滚后的棋盘信息掩盖选择时的实际位置。

## 验证证据

新增 `test_decision_contract.py` 共 34 个用例，包括：

- 同技能连续选择的回放与超时；过期超时不能回答新问题。
- 蛋、双胞胎的三个候选逐一选择，验证实际复制对象与显示候选一致。
- 催眠师每个目标及跳过；人字拖每个目标、跳过，以及正常移动是否消耗。
- 电灯泡同时有两组配对位置时选择每组及跳过。
- 啦啦队长的使用/拒绝，确认全部并列最后角色均受到效果。
- 非法提交后仍可正常回答原问题；角色归属和位置描述；火箭骰点预览。
- 房间层重复点击只结算一次；超时先发生/玩家提交先发生均不重复结算；重连保留问题、选项与原截止时间。
- 2/3/6 人模式下阵容单选/多选的数量、重复、非法角色及锁定后再次提交。

新增离线脚本 `probe_decision_branches.py`：32 场比赛，遇到 1,141 次选择，覆盖全部 16 种交互技能。对每个种子首次遇到的每种技能，用 pickle 隔离保存的待选状态，尝试所有公开选项及自动选择，然后继续推进 6 次操作。共 **490 个有效分支**、**504 次越权/过期/非法提交**通过；非法提交不改变公开状态或消耗原问题。

复现命令（仓库根目录）：

```sh
PYTHONPATH=apps/server/src apps/server/.venv/bin/python apps/server/scripts/probe_decision_branches.py
apps/server/.venv/bin/python -m pytest apps/server/tests -q
cd apps/web
npm test
npx tsc -b
```

前端纯函数测试验证预测与选骰的区分、换位代价，以及向后跟随时的对象和格子提示。未以浏览器验证布局、按钮视觉效果或动画期间的交互时序；未穷举每种技能在所有棋盘状态下的全部组合。此前发现的决斗长连锁仍属于独立问题，此次没有修改游戏触发规则。
