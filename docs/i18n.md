# 多语言与翻译

界面文案由 `i18next` + `react-i18next` 驱动，翻译文件是普通 JSON，可以直接交给 Weblate、Crowdin 之类的平台托管。

## 语言与目录

**英文是源语言**，所有键先用英文写一次，再翻译成其他语言。当前支持：

| 语言 | 目录 | 说明 |
| --- | --- | --- |
| `en` | `apps/web/src/i18n/locales/en/` | 源语言，键的定义以它为准 |
| `zh-CN` | `apps/web/src/i18n/locales/zh-CN/` | 简体中文译文 |

每个语言目录下有三个命名空间文件，结构必须与 `en` 完全一致：

| 文件 | 命名空间 | 内容 |
| --- | --- | --- |
| `app.json` | `app` | 大厅、按钮、错误码（`serverErrors.*`）等通用文案 |
| `race.json` | `race` | 比赛事件、技能决策、计分播报 |
| `athletes.json` | `athletes` | 36 名赛车手的名字、技能名、说明 |

## 在代码里取文案

默认命名空间是 `app`，其余命名空间用 `:` 前缀：

```tsx
const { t } = useTranslation();
t("selection.confirm");                      // app.json
t("race:event.diceRolled", { value: 5 });    // race.json
t("athletes:alchemist.abilityTitle");        // athletes.json
```

赛车手相关的文案一律按**稳定 id**（如 `alchemist`）取。服务端只保留 `id`、英文卡面名 `name` 和规则引擎句柄，不再携带任何译文；英文名只在 id 未知时兜底。

## 语言选择与优先级

`detectLocale()` 的判定顺序是：`?lang=` 查询参数 → `localStorage` → 浏览器语言 → 英文兜底。把 `?lang=zh-CN` 拼到地址后面就能直接进入中文界面，翻译平台可以用这个参数做“查看此处译文”的深链。

## 新增一门语言

1. 复制 `apps/web/src/i18n/locales/en/` 为 `locales/<新语言>/`。
2. 在 `apps/web/src/i18n/index.ts` 的 `SUPPORTED_LOCALES`、`LOCALE_LABELS` 和 `resources` 里登记这门语言。
3. 在 `apps/web/src/i18n/index.ts` 的 `matchLocale()` 里补上浏览器语言标签的匹配规则。
4. 运行 `npm test`，确认没有缺键。

## 接入翻译平台

三个 JSON 文件就是 i18next 的标准格式，平台侧选 **i18next JSON file** 即可，文件路径模板写成：

```text
apps/web/src/i18n/locales/{{language}}/{{namespace}}.json
```

这样平台的 `{{namespace}}` 正好对应 `app` / `race` / `athletes`，`{{language}}` 用 `en`、`zh-CN` 这样的 BCP-47 标签。仓库内的键名是英文短语（如 `race:decision.chooseDie`），在平台里会以键值对照的方式出现，翻译者看到键名就能判断上下文。

源语言用英文，所以平台上的语言代码 `en` 应设为**只读源语言**，翻译者只改其他语言。

### 平台选择

| 平台 | 适合场景 | 备注 |
| --- | --- | --- |
| [Codeberg Translate](https://translate.codeberg.org/) | 仓库已经放在 Codeberg | 免费，跑的是 Weblate，支持 Codeberg 账号单点登录 |
| Weblate Libre | 开源项目、仓库在 GitHub | 免费，要求项目**公开且带开源许可证** |
| Crowdin | 需要审校流程或商业支持 | 免费档对开源项目开放，界面更成熟 |

无论选哪个，**仓库需要先有 LICENSE 文件**——Weblate 的免费档和 Codeberg Translate 都要求能识别出开源许可证。

## 改文案时的注意事项

- 先改 `en`，再补其他语言；只改 `zh-CN` 会造成键漂移。
- 插值变量（`{{name}}`、`{{count}}`）在各语言里必须保持一致，顺序和个数都不能变。
- 服务端只回稳定的 `code`（见 `serverErrors.*`），不要在服务端拼中文句子。

## 防回退

`src` 下（`src/i18n/locales/` 除外）不应该再出现中文字面量，只有语言名称、来自服务端的哨兵值等少数例外。改界面代码时如果又写死了中文，多语言就会缺一块。
